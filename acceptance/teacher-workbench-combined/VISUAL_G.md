## Ranked remaining findings

### P2 — G-V1: excess framing materially reduces the visible investigation area

Across desktop, tablet, phones and native 200%, repeated navigation/context, large vertical gaps, expanded filter controls and repeated Work log headings push the actual work substantially lower than in the approved prototype. This is clearest at 1024 and native 200%, where the prototype exposes original work but the application initially exposes mostly framing; at 390 the original answer only begins near the fixed bottom navigation. The offset exists before response length or the number of concepts/students can account for it.

This is an unresolved visual fidelity/usability issue, **not evidence of lost responses or inaccessible panes**. The captured text and recorded pane probes contain the full work log, and scrolling is expected. A later focused correction should preserve the authorization/scope disclosures while reducing duplicated framing. No correction was made during this integration review.

### P2 — G-V2: Summary does not reproduce the prototype's supported-answer comparison structure

At 1440 the prototype Summary visibly includes **Answers fully correct, by situation**, separating first answers without help, answers after help/reading, immediate checks, teacher review checks and later reviews with denominators. The integrated Summary instead shows **Recorded activity** counts: submitted responses, responses with help, immediate retests, delayed reviews, displayed help and evaluations not accepted. Its delivered-intervention relationship is present and meaningful, but the comparison structure is different.

This is a genuine representation/capability difference, not merely one concept versus five or three responses versus five. G's source report deliberately replaces informal performance summaries with supported recorded counts. That conservative evidence choice should remain explicit; the integration must not claim full visual parity or invent missing comparisons. Independent acceptance should decide whether this bounded deviation is acceptable for the candidate.

### P3 — G-V3: response symbols and typography retain a different visual language

The prototype uses compact circular/diamond response marks and generally larger table labels; the application uses bordered square symbols, a compact 12px table and 11px table headings (`roster.css`), while dedicating more space to surrounding controls. Status meaning remains available in the visible legend, and the work-log concept names remain human-readable. This is a lower-priority visual difference, not a demonstrated evidence-integrity or contrast failure.

## Preserved structures and source caveats

The former missing-structure finding is materially addressed: a student-by-concept grid exists; selecting a student produces Ideas, a cross-session assessed-response log and Summary; exact-session actions remain visible in the content; intervention delivery/follow-up relationships are displayed from records. The screenshots and harness receipts support those narrower claims.

G's source report at `af4eec9:app/teacher/students/verification/ACCEPTANCE.md` remains relevant: the log includes assessed responses and recorded assistance for the selected assignment/source, **not every dialogue message**; intervention history is bounded to the latest 30 drafts; absent help or causal links are not inferred. The actual prototype's promise of the same complete timeline the student sees is therefore not fully established by these captures. This known coverage limit needs to remain in the final handoff; it must not be hidden as a fixture difference.

No P0/P1 failure is demonstrated in these G images. No statement here establishes final independent acceptance, full conversation completeness, physical-touch behavior or screen-reader usability. Composition and service/browser results remain separate evidence.
