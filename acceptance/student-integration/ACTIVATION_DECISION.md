# Recorded-history activation decision

**Keep disabled by default in this draft candidate.** The application requires the explicit server setting `NOTEBOOK_RECORDED_HISTORY=1`; absent or other values retain the independently authorized current-data fallback. This integration does not change that condition or enable it in a committed environment.

The isolated acceptance environment runs the same production build on two loopback origins: 3431 with the flag off and 3432 with it on. The second origin exists only to test the proposed mode. Both use fictional records and disabled providers.

Combined privacy, authorization, exact-source, snapshot-conflict, read-only and recovery evidence is reported in the final results and N6 handoff. Passing those checks establishes the tested safety behavior; it does not fill the recorded-history product and presentation gaps. The global Notebook remains a session index, historical concept titles and some events are unavailable, and full prototype parity is not accepted.

The activation handoff is therefore a separate, explicit review decision. Review the combined receipts, current-data fallback, remaining differences and independent N6 disposition before changing the runtime flag. No merge, deployment or activation is included in this task.
