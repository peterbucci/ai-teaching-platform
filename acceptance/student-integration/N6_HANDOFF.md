## Fixed independent findings

The earlier combined build reproduced the previously intermittent immediate-account-menu failure. Native click traces showed reader activity changing `true → false → true` before the account details opened; the first open frame still reported active. An observer refresh could undo synchronous deactivation during the same event. The integration owner added an owner-local transition guard in `c7bff74`; the auditor reviewed it and reran the unchanged strict assertion successfully. Earlier failed traces remain in [reader evidence](reader-timing/RESULTS.md). This was an observed state/timing defect, not observed historical evidence corruption.

A second combined run exposed an extra reading-acknowledgment request after explicit recovery of a lost response. [The JavaScript fetch trace](active/panes-1792965976607/report.json) records the original failed fetch ending at 686.9ms, the explicit retry returning 200 at 1071.6ms, and a third application fetch for the same delivery starting at 1072.7ms. The shared stack proves application reentry rather than a Playwright request-count artifact. A scroll/frame callback could run again after the in-flight flag cleared but before React removed its observer. The integration owner committed `b39e74d`, adding an effect-local attempted guard before the existing fetch. Independent source review finds it preserves visibility, delivery identity, server authorization and explicit retry ownership. The final b39e74d pane report passes all 13 original groups with 20 unknown-response repetitions (32 executions); the auditor inspected it. The auditor independently repeated the strict 60-cycle timing suite and 60 focused deterministic tests on b39e74d. Earlier c7bff74 evidence remains historical rather than being relabeled.
