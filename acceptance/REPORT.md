## Failures retained and harness corrections

No app failure was repaired during acceptance. Raw failures remain alongside corrected harness runs. Some JSON files receive whitespace-only formatting for repository compatibility; exact original bytes remain in adjacent .raw.json.log files, and the inventory records transformations and both hashes. Parsed JSON values are compared; no result or assertion changes during packaging.

- Initial Docker internal-network port exposure and a gateway-cached app address produced browser connection/502 failures. The verification gateway was corrected/reloaded; application source was unchanged.
- Earlier browser selectors, streaming/read-ack waits, wrong synthetic class selection and editor-tab assumptions were corrected in verification scripts. Earlier reports remain local and are summarized in the detailed reports. Main's original teacher invalid-assignment text matcher was too narrow; its safe denial passed in the explicit confirmation run.
- Two original synthetic history sessions were intentionally excluded by the student route's `live_demo` constraint. They were not relabeled. A new normal session with explicitly synthetic evaluator provenance supplied S-01.
- An unavailable disabled-help transport did not dispatch the operation the initial fault test expected. That attempted case is UNRUN, not an unknown-provider pass.
- PR116's optional `audio:check` failed with 503 because this isolated stack has no Piper speech service. The raw run remains failed; CI-aligned mandatory checks passed. Audio success is UNRUN and the optional suite is no longer in the default runner.
- Main approval fixture preparation reached the existing ten-drafts/hour budget after earlier runs. This is an environment/fixture saturation, not permission to reset the budget. Its failed preparation is retained; the later main check reused explicit existing synthetic draft snapshots through the established approval script and passed. It preserved the failed preparation log and did not reset the budget.
- Main's first all-files lint/format run caught new verification formatting and temporary helper files. Temporary helpers moved outside source and verification files were formatted. Separate production-baseline lint/format passed. Final all-files verification is recorded separately.
- Earlier browser harness versions wrote FAIL into JSON but exited zero. Reports, not those exit codes, are authoritative. Reusable scripts now fail the process for recorded FAIL and refuse to overwrite reports.
- The combined integration run encountered PostgreSQL PANIC 58030 (`could not fdatasync WAL file: Input/output error`), followed by Docker API 500 errors. Host C: had approximately 0.01 GiB free. All runtime acceptance stopped. Removing only regenerable dependencies/build outputs from this task's three later worktrees restored 9.15 GiB free; sources, evidence and database volumes were preserved. The shared Docker daemon was not restarted and database recovery was not verified. Earlier passes retain their timestamps; no post-incident durability claim is made. See the [incident record](evidence/combined/STORAGE_INCIDENT.json).
