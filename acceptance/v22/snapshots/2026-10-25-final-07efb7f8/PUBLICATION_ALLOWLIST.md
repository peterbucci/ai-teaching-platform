# Publication provenance and privacy review

The new snapshot is an explicit, hash-pinned selection from this verification run. Nothing copies the visualization root, runtime directory or shared data wholesale. Earlier PR #122 snapshots remain unchanged; failed and passing local reports remain intact.

The exact final selection, exclusions, transformations and source/published SHA-256 hashes are in [PUBLICATION_PLAN.json](publication/PUBLICATION_PLAN.json). [PUBLICATION_PATHS.json](publication/PUBLICATION_PATHS.json) maps original paths to separately named published derivatives. [COPY_RECEIPT.json](publication/COPY_RECEIPT.json) records the completed copy and hash verification. These machine receipts supply the final inventory time and counts; provisional earlier scans do not establish coverage of later files.

| Published material | Treatment |
| --- | --- |
| Final reports, integration matrix and ranked findings | Current candidate only; passing, failing and unrun cases remain distinct. |
| Integration, ancestry, preservation and independent recomposition receipts | Exact commits, trees and owner scope retained; independent Git object database excluded. |
| Guarded suite receipts and selected logs | Commands, outcomes and preflights retained; private environment/configuration excluded. |
| Browser/API/service reports | Fictional learning IDs, source versions, request/submission IDs, evaluations and assistance remain attributable. Private guard fields are removed only in separately named derivatives. |
| Original application/prototype images | Bytes, dimensions and hashes unchanged. Fixture and lifecycle differences labeled; native 200% uses complete original CDP images with cropped originals retained. |
| Verification helpers and adaptation provenance | Separate from application source; original verifier failures preserved. Provider credentials are loaded privately and never published. |
| Final persistence evidence | Exact before/after group hashes and restart identity retained. Complete scoped SQL exports stay private by publication policy; they are not needed to publish the 17-group equality result. No populated credential fields were detected in these four exports. |

Excluded material includes environment files, credentials, cookies/browser profiles/storage exports, Docker configuration or inspect output containing private environment values, database dumps/volumes, live lock ownership files, dependency trees, Git objects, prototype vendor runtime/export archive and the local project reference. Reviewed runtime manifest summaries have distinct names. The published student seed receipt contains fictional record IDs and the name of its credential environment setting, not a password value; actual credentials remain in the excluded private environment.

The publication scan compares known environment-secret values in memory and checks sensitive fields/content without printing their values. It preserves source hashes for excluded artifacts. Guard ownership tokens are control metadata, not learning evidence. Request UUIDs and accepted-evaluation identities are retained. A bounded scan is not proof that arbitrary text or pixels can never contain a secret; images and final selected paths receive separate review.

JSON guard-owner token fields are removed from public derivatives. Historical verifier source and release instructions retain the exact identifier of a guard already released, so the pinned executable remains reproducible. That identifier is not an authentication credential and grants no application or database access; this publication does not claim that every historical control identifier was removed.

Report narratives sometimes identify the original local `report.json`. Use the path mapping for its public `.sanitized.json` equivalent. Original and derivative hashes are explicitly distinguished. No screenshot pixels or historical report outcomes are altered to obtain a pass.
