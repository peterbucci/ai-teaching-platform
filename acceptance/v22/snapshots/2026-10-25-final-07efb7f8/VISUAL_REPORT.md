The approved prototype presents whole-course priorities, all assignments and unfinished lesson/intervention resume entries. These absent structures are not explained by fixture counts. At 390 the first priority is near the bottom; at 320 it is below the fixed navigation at initial scroll; native 200% first view contains only heading/actions/scope controls. Source evidence: `app/teacher/data.ts:27`, `app/teacher/page.tsx:56,59,229,264`. Reproduce via the gallery's Overview URL with the saved assignment; compare the desktop rail and mobile first viewport. This is an existing scope/completeness gap, not a newly proven integration regression.

**P2 · #116 / #8 — Roster and student work log completeness.** The app shows an expandable Students directory rather than per-concept chronological outcome/help marks and an intervention column. The dedicated student Ideas / Work log / Summary experience remains absent; existing session details are not a substitute for this cross-session view. Source: `app/teacher/students/page.tsx:79–198`; this file is unchanged from main in the candidate. The prototype-only `roster-student` gallery section is explicitly **Not verified** for a matching application screen.

**P2 · #116 / #8 / #21 — Insights/Patterns structure.** Learning Insights retains the inherited results-by-concept, nested pattern histories, student responses and intervention sections rather than a contextual concern investigation.
