## Verification infrastructure issues retained separately

- Docker originally hung following an earlier workstream's low-disk incident. The user authorized a shared Docker Desktop restart. That restored the daemon, not proof that the earlier database was repaired.
- Default subnet pool exhaustion blocked initial new-stack startup; explicit unused private ranges allowed startup. Original failure and changed configuration are retained.
- Initial local test command found an empty dependency junction; a known existing installed dependency tree was then used. The later Docker production build performed locked dependency installation.
- A bracketed Next.js route path omitted four colocated tests under Node's glob handling; the explicit-import launcher executed all 17. Both earlier and final logs are retained.
- Initial screenshot readiness used `networkidle` and timed out; final heading/font/paint readiness captured all intended views. The zero-capture result remains evidence.
- The bounded accessibility run stopped on a strict selector matching two transient Next.js page elements. This is a harness failure, not a demonstrated application accessibility defect; remaining steps are unrun.
- Host headroom later fell below the storage-recovery runtime threshold. Further database/browser work stopped. This is an environment blocker, not a fabricated application failure.
