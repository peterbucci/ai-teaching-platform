FINDINGS

C1 — P2 — Implicit assignment selection is lost on shared navigation
Owner: #117, with shared-shell contract coordination in #116 / #114.
Evidence: #117 app/teacher/assignments/page.tsx:30 resolves selection with selected.id but :33 renders TeacherFrame without context. app/teacher/assignments/load.ts:122-125 selects the first filtered assignment when the URL has no assignment. #116 app/teacher/navigation.tsx:35-48 reconstructs context from URL and optional server props; lib/teacher/workspace-contracts.ts does not carry class/status. app/teacher/data.ts:27 falls back to the first global teacher assignment when assignment is absent.
Reproduction: Use a fictional teacher with classes A and B, with A sorted first. Open Assignments, choose Class B and apply filters. The selected detail shows B's first assignment while the URL contains class/status, not assignment. Click Evidence or Teaching Desk in the shared shell. The generated URL lacks B's assignment and those pages choose A's first assignment.
Expected: The visible selected assignment remains the authoritative shell scope.
Impact: Teacher moves from a selected assignment to a different class's authorized evidence without requesting that change. This is context loss, not an authorization bypass. A single-class fixture would miss it.
Verification level: Confirmed by code-path inspection; browser reproduction pending.

C2 — P2 — Full-session return from assignment progress goes to Insights
Owner: #117 plus #116 shared return contract.
Evidence: #117 app/teacher/assignments/progress-model.ts:62-72 produces session URLs with assignment/origin/student/concept and an attempt hash, but no return destination or assignment progress/list context. #116 app/teacher/sessions/[sessionId]/page.tsx:57-64 defaults absent returnTo to insights; :86-105 supports no Assignments return destination. lib/teacher/workspace-contracts.ts:15 likewise excludes it.
Reproduction: Open assignment Class progress; select a student/concept cell; open Full session evidence; activate the displayed Back link. It opens Learning insights rather than the selected assignment progress cell. Class/status filters and the progress tab are lost.
Expected: An explicit contextual return restores assignment progress with student/concept/list selection and focus. Browser Back is a separate requirement and may still work.
Verification level: Confirmed by generated route and destination code; browser focus restoration unrun.

C3 — P2 — Raw URL scope overrides corrected saved-intervention scope in the shell
Owner: #116, shared navigation and intervention handoff.
Evidence: #116 app/teacher/interventions/page.tsx:70-75 resolves the saved draft context using snapshotInterventionContext; app/teacher/interventions/snapshot-context.ts:9-19 restores persisted assignment/origin/concept/misconception/starting responses. However app/teacher/navigation.tsx:44-47 spreads raw URL parameters after the resolved server context and replaces seedAttempt from the raw URL.

The intervention displays its persisted scope correctly. Follow the shared-shell Evidence link: the link contains the stale URL concept/origin instead of the displayed draft's saved evidence scope. A stale same-assignment attempt outside that scope can also be reintroduced.
Expected: Shared navigation from a saved artifact uses the authorized persisted context shown on the page.
Important limit: A mismatched assignment is explicitly rejected by snapshotInterventionContext; this finding does NOT claim cross-assignment acceptance or a permissions leak.
Verification level: Confirmed precedence mismatch by inspection; exact browser case pending.

C4 — P2 — Lesson-title search becomes an evidence-text filter
Owner: #116 shared navigation, coordinated with #118.
Evidence: #118 app/teacher/lessons/page.tsx uses q to filter lesson titles and submits a GET search form to /teacher/lessons. #116 app/teacher/navigation.tsx:35-48 captures that same q and :63-67 copies it into every navigation destination. #116 app/teacher/evidence/selection.ts:80-86 interprets q as student/question/original-answer search instead.
Reproduction: Search Lessons for an existing title that does not occur in the selected assignment's student names/questions/responses; click Evidence in the shared shell. Evidence opens with the lesson-title query and hides its response list. The reverse direction can similarly hide Lessons after an evidence-text search.
Expected: Page-local searches stay scoped to their owning page, or are deliberately cleared when changing destinations. Shared identity/origin context can remain.
Verification level: Confirmed conflicting semantics and unconditional propagation by inspection; browser reproduction pending.

C5 — P3 integration gap — Published-lesson handoff does not enter the new assignment builder
Owners: #118 and #117.
Evidence: #118 app/teacher/lessons/[lessonId]/page.tsx retains an unscoped Open class assignments link and the legacy CreateClassAssignment control in a disclosure; #117 adds /teacher/assignments/new?lesson=<id>&version=<version> and a separate recovery-aware CreateAssignment component. The new route is not used by #118's published lesson view.
Reproduction: Open an exact published version in Lessons, choose Open class assignments, then New assignment. The new builder starts with its own first catalog choice instead of the published version just reviewed. Alternatively use the legacy creation disclosure, which does pass the exact version but is a second creation/recovery experience.
Expected integration decision: Agree one deliberate exact-version handoff into the new builder, or document/review the retained separate route. Do not call this an immutable-version failure: the legacy form correctly passes the selected version and the new builder shows its chosen version.
Verification level: Static integration gap; not a service or authorization defect.
