Passage text starts around y=710 on phones. This is a substantial control area, but no equivalent student-reading prototype was captured, so it is recorded as a density observation rather than a demonstrated Workbench mismatch. The short two-paragraph passage does not test long-document reading.
- **Student conversation:** desktop images show one composer, the original question, help fallback, and then the saved original answer with an explicit evaluation action. One preserved-session image contains `Please wait…`; the final saved-answer image also shows a pending row. These are actual captured states, not proof of a stuck operation. The later receipt proves saved data/reload, not that the pending row's presentation passed visual acceptance. No mobile conversation screenshots are available in this chain.

The structural discrepancy should be reviewed by PR #116 with PR #120; conversation rendering remains a PR #113 integration concern.
