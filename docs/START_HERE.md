# Start Here — Learning Pulse

**New to coding? That's okay.** We're using AI coding assistants to help build our hackathon project. You don't need to know how to set up a database or write code before you can start contributing.

This page is the **quickest way to get started**. If you'd rather understand each step or do the setup yourself, see [Getting Started](GETTING_STARTED.md).

## 1. Get access to the project

Open our [GitHub repository](https://github.com/peterbucci/ai-teaching-platform) and [team project board](https://github.com/users/peterbucci/projects/7).

You can view the public repository with or without a GitHub account. **To contribute changes**, you'll need a GitHub account and the appropriate repository access. Ask a teammate if you're unsure.

## 2. Choose an AI coding assistant

Use **Codex, Claude Code, or another coding assistant** you're comfortable with. You only need **one**.

Follow [Codex setup](CODEX_SETUP.md) or [Claude Code setup](CLAUDE_CODE_SETUP.md) to install your assistant or open its web-based coding environment, sign in, and connect to **`peterbucci/ai-teaching-platform`**. A local assistant opens a project folder on your computer; a cloud assistant connects to GitHub.

You don't need Docker for every task. A cloud environment or sample data may be enough to get started; ask the team if you're unsure.

## 3. Copy this setup prompt

Paste the entire message below into your coding assistant:

> I'm new to this project and would like your help getting ready for my first task.
>
> **Repository:** https://github.com/peterbucci/ai-teaching-platform
>
> Please:
>
> 1. Check whether you can access the repository. If not, help me clone it or connect to it.
> 2. Read `README.md`, `AGENTS.md`, `PROJECT_CONTEXT.md`, and the relevant setup instructions.
> 3. Check what my computer or coding environment needs for the kind of work I'll be doing.
> 4. Do as much of the setup as you safely can. If needed, help configure the project, install dependencies, and start the app.
> 5. Run appropriate checks to confirm what actually works and help me troubleshoot anything that doesn't.
>
> **Please keep it beginner-friendly:** Explain unfamiliar terms simply and give me one action at a time when I need to do something myself. Ask before installing system software, changing important settings, overwriting files, or deleting data. Keep passwords and API keys private; never print them in chat or commit them to GitHub. Don't edit the app's source code, create commits, or push changes during setup.
>
> When you're finished, give me a short summary: **what's ready, what you tested, what's still needed, and whether I can start my first issue.**

## 4. Follow along and approve important steps

Your assistant can often handle technical setup for you. You may still need to sign in, approve an installation, or start an application such as Docker. **You don't need to figure everything out alone.**

If the assistant asks you to pay for something, share a secret, delete data, or make a major change, **check with the team first**.

## 5. Confirm you're ready

Ask your assistant to show you what it successfully checked. It's okay if some parts aren't ready yet—for example, a design task may not require a working database.

Once you're set up, open the [project board](https://github.com/users/peterbucci/projects/7) and ask the team which issue to start with. **Don't begin changing code directly on `main`** (our shared version of the project).

**Want more detail?** Read [Getting Started](GETTING_STARTED.md). After setup, follow our [team contribution guide](../CONTRIBUTING.md) and [First Task](FIRST_TASK.md) walkthrough.
