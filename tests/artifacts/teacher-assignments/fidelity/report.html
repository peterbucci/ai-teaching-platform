Deliberate differences and limits

  • Unavailable metadata stays unavailable. Publication timestamps and revision notes are not fabricated where the current loader does not provide them.
  • The index uses actual enrollment. Class rows show roster counts rather than loading every student history for every assignment to imitate a prototype participation label.
  • Full content-version identifiers remain intact. They may wrap differently from the prototype's short sample labels; links and assignment identities retain the exact value.
  • The current shared sidebar remains. Shared workspace/navigation files are outside this correction's ownership. This is an integration dependency, not accepted full fidelity.
  • The evidence-source filter remains available. Prepared synthetic histories and live demo records must remain distinguishable.
  • Preview privacy remains enforced. Teacher-only criteria, hypotheses, diagnostic prompts, and future feedback stay out of the student projection. Opening a preview creates no session and marks no assistance as shown.
  • The fixtures differ. The application uses 24 students / 63 answers; the prototype uses 18 / 68. Compare structure, labels, density, and behavior against equivalent states.

Integration handoff

The Lessons-to-Assignments handoff uses the existing route with exact selected identities:

/teacher/assignments/new?lesson=<lessonId>&version=<publishedVersion>&class=<classId>

  • Lessons owner: pass the published lesson ID, exact version, and authorized class where available. Assignments consumes the existing review/resolver contracts.
  • Workbench owner: integrate the shared global header, assignment band and mobile bottom navigation, then repeat paired desktop/mobile captures. Shared workspace components and navigation contracts were not changed in this correction.
  • Evidence owner: existing evidence routes receive authorized assignment/student/concept context; progress creates no extra evidence store or evaluator.
  • Implementation boundary: assignment-specific UI and tests/artifacts only. No new services, shared-file changes, assignment persistence system, or student-session mutations are introduced by this fidelity pass.
