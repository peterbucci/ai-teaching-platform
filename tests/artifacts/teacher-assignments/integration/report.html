Implemented contracts

C2: progress → session → progress

Outgoing session links carry returnTo=progress, assignment, origin, progress view, pane, class/status filters and optional attempt identity. Original progress selection uses progressStudent and progressConcept. The target session identifies whose work is opened; target student/concept query fields are omitted. This allows a teacher to inspect a Questions or Study sessions row for another student and return to the original selection.

The shared receiver authorizes the session/attempt and independently validates the return roster and concept against the authorized assignment and exact published version. It maps the namespaced selection back to student/concept in the progress URL. Return context grants no access.

Return context Page-owned focus target
Details cell-evidence
Grid with a selected student and/or concept ap-selection-<student or all>-<concept or all>
Concepts with a selected concept ap-selection-all-<concept>, the visible concept column.
Questions, Study sessions, or no visible selection progress-main

The region declares data-workspace-restoration="page". Restoration accepts only fixed/context-derived targets and also handles hashless history. The final fix avoids automatically scrolling the main view during initial focus restoration.

C5: exact published version → inactive assignment

/teacher/assignments/new?lesson=<exact lesson>&version=<full published version>[&class=<authorized class>]

The receiver rejects orphan versions, unknown exact pairs and foreign classes, then uses the existing authorized content resolver. Exact handoffs cannot fall back to another publication. Legacy lesson-only and unscoped picker behavior remain compatible. Creation, publication and activation remain separate decisions; pending creation requests retain their immutable idempotency payload.

V04/V05: discovery and shared spacing

Discovery groups by real lesson identity, exact version and classroom assignment. Assigned publications appear before unassigned publications and drafts. Long IDs show an eight-character prefix and six-character suffix, with the full immutable ID available through a native disclosure; routes and requests keep the full value. Closed desktop filters share the heading row; opening them restores the full-width form. Active filters initially open, and teachers can collapse them.

Normal discovery/review content consumes the shell inset once: 28px desktop, 14px through 800px, 12px through 360px. Resolved progress uses the agreed full-width frame and one internal heading/content gutter, with its own details pane. Shared shell and evidence/session services remain owned by their respective agents.
